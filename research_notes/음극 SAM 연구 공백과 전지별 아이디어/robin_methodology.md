## Key Question 1 — What exactly are the stages of the Robin loop, and which agent does what?

### Takeaway
Robin is a fixed, mostly deterministic pipeline (not a free-form agent) with three macro-stages — (A) experimental-assay selection, (B) therapeutic-candidate generation and ranking, (C) experimental data analysis that feeds "experimental insights" back into a second run of stage B. Literature agents Crow (fast PaperQA2 summaries) and Falcon (deep reports) do all literature grounding; a plain LLM (o4-mini by default) does query writing, idea generation, goal synthesis and pairwise judging; Finch is a Jupyter/R data-analysis agent; humans run the wet lab.

### Cited Findings

**Overall architecture and the agents**
- FutureHouse describes Robin as orchestrating "Crow, Falcon, and Finch to propose and pre-clinically validate novel treatments for any human disease" and as "the first multi-agent system for biological discovery to integrate hypothesis generation, experimental strategy, data analysis, and follow-up insight generation in one continuous workflow." **[PAPER-via-secondary]** — [FutureHouse blog](https://www.futurehouse.org/research/demonstrating-end-to-end-scientific-discovery-with-robin-a-multi-agent-system) (as summarised in search results); Nature article: [A multi-agent system for automating scientific discovery](https://www.nature.com/articles/s41586-026-10652-y), published 19 May 2026, authors Ghareeb, A.E., Chang, B., Mitchener, L. et al.
- Per the preprint summary: Crow does concise literature synthesis; Falcon does deeper synthesis and writes the detailed candidate reports; Finch is a Jupyter-based data-analysis agent for flow cytometry and RNA-seq running in Docker; OpenAI o4-mini synthesises evidence and generates hypotheses; Claude 3.7 Sonnet performs pairwise hypothesis judging; the system is built on FutureHouse's Aviary framework. **[PAPER-via-secondary]** — [GitHub issue summary of arXiv 2505.13400](https://github.com/jjakimoto/research-issues/issues/1656)
- The Nature-based press digest likewise states Robin "uses both OpenAI o4-mini and Anthropic Claude 3.7" and is "designed to aid discovery in the field of experimental biology." **[PAPER-via-secondary]** — [Nature Asia press release](https://www.natureasia.com/en/info/press-releases/detail/9330) (search-snippet)
- In the released code the agent assignment is explicit: `assay_lit_search_agent = JobNames.CROW`, `assay_hypothesis_report_agent = JobNames.CROW`, `candidate_lit_search_agent = JobNames.CROW`, `candidate_hypothesis_report_agent = JobNames.FALCON`. The notebook log shows the Crow job is literally `job-futurehouse-paperqa2` ("Starting literature search for 5 queries using job-futurehouse-paperqa2"). **[CODE]** — [configuration.py](https://raw.githubusercontent.com/Future-House/robin/main/robin/configuration.py); [robin_full.ipynb](https://raw.githubusercontent.com/Future-House/robin/main/robin_full.ipynb)
- Default LLM for all non-literature steps is `o4-mini` via LiteLLM (any LiteLLM model can be substituted). **[CODE]** — [configuration.py](https://raw.githubusercontent.com/Future-House/robin/main/robin/configuration.py); [README](https://raw.githubusercontent.com/Future-House/robin/main/README.md)
- The README instructs: "In order to run Robin as used in the manuscript, only input the name of a disease, with no other text. If you wish to optimize how Robin searches for experimental models and therapeutic candidates, we suggest changing the internal prompts of Robin (via prompts.py), not the initial input to the pipeline." **[CODE]** — [README](https://raw.githubusercontent.com/Future-House/robin/main/README.md)

**Stage A — Experimental assay selection (`experimental_assay()` in assays.py)** **[CODE]** — [assays.py](https://raw.githubusercontent.com/Future-House/robin/main/robin/assays.py)
- A1. *Query generation* (LLM): system prompt casts the model as a "highly experienced biomedical research strategist"; user prompt asks for `num_queries` literature queries (separated by `<>`), each "30+ words", "Don't look up specific drugs", covering "both … the general biochemistry and mechanistic underpinnings of {disease} as well as … the assays." Paper run: `num_queries=5`.
- A2. *Literature review* (Crow/PaperQA2): each query is sent to the Edison platform as a separate job; the answers are concatenated into `assay_lit_review_output` and saved to `experimental_assay_literature_reviews/`.
- A3. *Assay proposal* (LLM): prompt = "professional biomedical researcher … early-stage drug discovery and validation in vitro … Generate exactly {num_assays} distinct assay ideas … prioritize simplicity, speed of readout, biological relevance, and direct measurement of functional endpoints." Output is a strict JSON array of `{strategy_name, reasoning}`. Paper run: `num_assays=10`.
- A4. *Per-assay detailed report* (Crow): for each proposed assay, a report query is built as `ASSAY_HYPOTHESIS_SYSTEM_PROMPT + assay text + ASSAY_HYPOTHESIS_FORMAT`; the required format has four sections: **Assay Overview / Biomedical Evidence / Previous Use / Overall Evaluation** ("Strengths and weaknesses").
- A5. *Pairwise ranking* (LLM judge) over `uniformly_random_pairs(n=num_assays)`; results written to `experimental_assay_ranking_results.csv`; Bradley–Terry strengths computed with `choix.ilsr_pairwise(num_assays, games, alpha=0.1)`; the top assay is selected. Paper run log: "Comparing Hypotheses: 100% 45/45" (all C(10,2)=45 pairs) → "Experimental Assay Selected: Phagocytosis assay".
- A6. *Goal synthesis* (LLM): a one-sentence "research goal for the *next* stage … focused on identifying novel therapeutic compounds to test using this assay." Paper run output: "Use a high-throughput fluorescence-based RPE phagocytosis assay to identify novel compounds that enhance photoreceptor outer segment clearance, thereby restoring RPE function and preventing progression of dry age-related macular degeneration."

**Stage B — Therapeutic candidate generation (`therapeutic_candidates()` in candidates.py)** **[CODE]** — [candidates.py](https://raw.githubusercontent.com/Future-House/robin/main/robin/candidates.py)
- B1. *Query generation* (LLM): asks for `2 × num_queries` queries — `num_queries` on "the therapeutic landscape" and `num_queries` on "the biological and mechanistic aspects" of the disease — with explicit priorities: Target Validation, Efficacy in Relevant Models, Mechanism Confirmation, Pharmacokinetics/Safety Data. Paper run: 10 queries.
- B2. *Literature review* (Crow) on those queries; saved to `therapeutic_candidate_literature_reviews/`.
- B3. *Candidate generation* (LLM): "Generate exactly {num_candidates} candidate proposals", each a block `<CANDIDATE START> CANDIDATE: / HYPOTHESIS: / REASONING: <CANDIDATE END>`; must be "a single agent, not a combination", "commercially available (mention catalog numbers if applicable)", "novel for treatment of the disease and ideally address novel targets … not tested in prior studies". Paper run: `num_candidates=30`.
- B4. *Per-candidate deep report* (Falcon): query = `CANDIDATE_LIT_REVIEW_DIRECTION_PROMPT + candidate block + CANDIDATE_REPORT_FORMAT`; required sections: **Overview of Therapeutic Candidate / Therapeutic History / Mechanism of Action / Expected Effect (in the proposed assay) / Overall Evaluation**. Reports are then post-processed by an LLM "editor" that reformats citations to APA 7th with the instruction "DO NOT MAKE UP ANY REFERENCES THAT ARE NOT IN THE SOURCES LIST. IF YOU ARE NOT SURE ABOUT A REFERENCE, JUST SAY (Unknown Reference)." Saved to `therapeutic_candidate_detailed_hypotheses/`.
- B5. *Pairwise ranking* (LLM judge) → `therapeutic_candidate_ranking_results.csv` → `choix.ilsr_pairwise` → `ranked_therapeutic_candidates.csv` with a `strength_score` column. Paper run log: "Calling choix.ilsr_pairwise with n_items=30 and 298 games" (300 pairs attempted, 2 JSON-parse failures).

**Stage C — Experimental data analysis and feedback (`data_analysis()` in analyses.py)** **[CODE]** — [analyses.py](https://raw.githubusercontent.com/Future-House/robin/main/robin/analyses.py); [prompts.py](https://raw.githubusercontent.com/Future-House/robin/main/robin/prompts.py)
- C1. Humans run the experiment and drop raw data (e.g., `.fcs` flow-cytometry files + plate metadata) into a folder.
- C2. *Parallel Finch analysis*: the same analysis prompt (chain-of-thought template + R coding guidelines + task-specific query) is run as **5 independent Finch trajectories** (`PARALLEL_ANALYSIS = 5`, job `job-futurehouse-data-analysis-crow-high`, R, `max_steps=30`, 15-min timeout), each producing `flow_results.csv` with columns `drug, mean_intensity, std_error, p_val, adj_p_val`.
- C3. *Consensus step*: a single Finch run meta-analyses the 5 result files ("consider what is a suitable method to combine the p values"), outputs `consensus_results.csv` and a bar plot with significance asterisks. For RNA-seq the consensus is "mode of log2FC and adjusted p values" plus a `top_genes.csv` of the top 10 consensus genes.
- C4. *Data interpretation* (LLM, "expert biochemist"): returns four `<>`-separated fields — list of drugs tested; summary of key findings; specific questions raised; mechanistic insights.
- C5. *Follow-up suggestion* (LLM, "expert experimental biologist and research strategist"): proposes follow-up assays as "Assay Name / Reasoning" pairs, or none.
- C6. *Feedback*: `experimental_insights = {analysis_summary, mechanistic_insights, questions_raised, followup_suggestions}` is passed back into `therapeutic_candidates()`; the appendage "Experimental tests have been conducted previously to {goal}. Here is a summary of the results … mechanistic insights … important questions …" is added to **both** the query-generation system prompt and the candidate-generation user prompt, and the whole of stage B (10 queries → Crow → 30 new candidates → Falcon → 300 pairwise comparisons) is re-run, with outputs suffixed `_experimental`.
- The repo's analysis prompt library hard-codes only two assay types, `flow_cytometry` and `RNA_seq`; anything else requires writing a new `ANALYSIS_QUERIES` / `CONSENSUS_QUERIES` entry. **[CODE]**

**Paper-level narrative of the loop (dAMD case)** **[PAPER-via-secondary]** — [GitHub issue summary](https://github.com/jjakimoto/research-issues/issues/1656); [search summary of the preprint](https://arxiv.org/pdf/2505.13400)
- Stage sequence reported for the paper: (1) review 151 papers and propose 10 disease mechanisms/assays → team selected RPE phagocytosis; (2) synthesise ~400 papers and nominate 30 existing drugs; (3) rank them in an LLM-judged tournament; (4) first wet-lab round on five candidates (Exendin-4, Fingolimod, MFGE8, Y-27632, AICAR+TUDCA); (5) second round on 10 drugs; (6) bulk RNA-seq analysed by Finch.
- "Robin reviewed about 400 papers and proposed 30 existing drugs for testing. Falcon produced comprehensive evaluation reports on each of these molecules, which were ranked in an LLM-judged tournament." — [search summary citing arXiv 2505.13400](https://arxiv.org/pdf/2505.13400)
- Humans chose materials (substituting pHrodo beads for the agent-proposed photoreceptor outer segments), ran the ARPE-19 phagocytosis assays, supplied the flow-cytometry data, and did RNA-seq demultiplexing/alignment before Finch analysis. — [GitHub issue summary](https://github.com/jjakimoto/research-issues/issues/1656)
- The preprint's original agentic controller "almost always called tools in the same order, so the authors later replaced it with a deterministic notebook." — [GitHub issue summary](https://github.com/jjakimoto/research-issues/issues/1656)

### Inferences
- **[INFERENCE]** The released code is a deterministic DAG of LLM calls; "multi-agent" refers to delegating literature search/report writing to PaperQA2-based agents (Crow/Falcon) and data analysis to Finch, not to agents negotiating with each other. For a hand-run or Claude-Code-run battery version, the whole loop can be reproduced with: one LLM for query writing/ideation/judging, one literature-grounded summariser with citations (any RAG over your paper corpus), and one code-executing analysis agent.
- **[INFERENCE]** The two-tier design (fast Crow for breadth; deep Falcon only on the shortlisted ideas) is a cost-control pattern: the expensive deep review is spent only on the N generated candidates, not on the background queries.
- **[INFERENCE]** Translating the stage names to batteries: "disease" → failure mode/target property (e.g., Li-metal anode SEI instability); "assay" → test protocol/cell format (e.g., Li||Cu CE test, symmetric-cell impedance); "therapeutic candidate" → intervention (e.g., a specific SAM molecule/electrolyte additive with a CAS number as the analogue of a "catalog number"); "flow_cytometry analysis prompt" → a cycling/EIS analysis prompt with a fixed output CSV schema.

### Gaps
- The Nature paper's Methods and Supplementary Information could not be read (network block), so any differences between the arXiv version and the final Nature version (other than the addition of KL001 as a second confirmed compound, noted in search summaries) are unknown.
- Exact Crow/Falcon internal parameters (number of papers retrieved per query, model behind PaperQA2) are not exposed in the Robin repo; they live in the Edison platform.

## Key Question 2 — How are candidate hypotheses ranked (tournament format, criteria, number of comparisons)?

### Takeaway
Ranking is a pairwise "tournament" judged by an LLM acting as a "drug development committee member": every possible pair is compared when there are ≤25 items (round robin), otherwise 300 uniformly random pairs are sampled; wins/losses are converted to a scalar strength via a Bradley–Terry–Luce model (`choix.ilsr_pairwise`, regularisation α=0.1). It is **not** Elo. Judging criteria are stated in priority order: evidence strength > mechanism clarity/directness > safety > feasibility (incl. delivery/ADME) > novelty (only if supported).

### Cited Findings
- Pair sampling: `uniformly_random_pairs(n_hypotheses, seed=621, n_games=None)` — "max_possible_games = n(n−1)/2; if n_games is None: n_games = min(300, max_possible_games)"; pairs are drawn with `random.sample` from all unordered pairs without replacement (so each pair is judged at most once in a run). **[CODE]** — [utils.py](https://raw.githubusercontent.com/Future-House/robin/main/robin/utils.py)
- The preprint summary states the same rule in words: "With 25 or fewer hypotheses, every pair is compared in a round-robin tournament. Above 25, the system samples 300 comparisons. Pairwise outcomes are converted to rankings with Bradley-Terry-Luce strength estimates." **[PAPER-via-secondary]** — [GitHub issue summary](https://github.com/jjakimoto/research-issues/issues/1656) (Note: C(25,2)=300, which is why 25 is the threshold.)
- Strength estimation: `choix.ilsr_pairwise(n_items, games, alpha=0.1)` (Iterative Luce Spectral Ranking for Bradley–Terry); items sorted by `strength_score` descending. **[CODE]** — [assays.py](https://raw.githubusercontent.com/Future-House/robin/main/robin/assays.py), [candidates.py](https://raw.githubusercontent.com/Future-House/robin/main/robin/candidates.py)
- Comparisons run concurrently (`max_concurrent_requests=100`); each judge call sees the two full reports and must return JSON with fields `Analysis`, `Reasoning`, `Winner` ("(winner_name, winner_id)"), `Loser`. Malformed JSON is logged and the pair is dropped (paper run: 298/300 successes in both rounds). **[CODE]** — [utils.py](https://raw.githubusercontent.com/Future-House/robin/main/robin/utils.py); [robin_full.ipynb](https://raw.githubusercontent.com/Future-House/robin/main/robin_full.ipynb)
- Assay-ranking criteria (system prompt): "based strictly on the presented scientific evidence, scientific novelty, methodological rigor, and logical interpretation, not on the persuasive quality or wording of the proposal documents … Preference for in vitro strategies that prioritize simplicity, speed of readout, biological relevance, and direct measurement of functional endpoints … simple to perform in standard lab setting." **[CODE]** — [prompts.py](https://raw.githubusercontent.com/Future-House/robin/main/robin/prompts.py)
- Candidate-ranking criteria (system prompt), verbatim headings and order: "1. Strength and Relevance of Supporting Evidence (Highest Priority)" [Existing Data; Relevance to the Problem; Negative Evidence — "a strong deterrent"; Quality of References]; "2. Mechanism of Action (MoA) – Clarity, Plausibility, and Specificity" [Clarity & Detail; Directness — "Prefer hypotheses targeting core, upstream issues"; Specificity & Target Biology]; "3. Safety, Tolerability, and Risk Profile (High Priority)"; "4. Feasibility of Experimental Plan and Drug Delivery" [Methodological Rigor; Model System Relevance; Drug Delivery to Target/ADME-PK]; "5. Scientific Novelty (Balanced with Evidence and Safety) — Novelty is valued, but *only if supported by plausible science and a reasonable safety outlook*." Objective: "select the hypothesis with the highest probability of successful experimental outcome AND eventual translation into a viable therapy." **[CODE]** — [prompts.py](https://raw.githubusercontent.com/Future-House/robin/main/robin/prompts.py)
- Judge validation reported in the paper: the LLM judge's top-10 "averaged 7.25 of 10 matches with experts' top-ten hypotheses"; the judge "repeated the same choice in 88% of duplicate comparisons, versus 61% for human experts." **[PAPER-via-secondary]** — [GitHub issue summary](https://github.com/jjakimoto/research-issues/issues/1656)
- Judge model in the paper was Claude 3.7 Sonnet; in the open-source default it is whatever `llm_name` is (o4-mini). **[PAPER-via-secondary / CODE]** — [GitHub issue summary](https://github.com/jjakimoto/research-issues/issues/1656); [configuration.py](https://raw.githubusercontent.com/Future-House/robin/main/robin/configuration.py)
- Example of a judge output logged in the paper run (Elamipretide vs Canakinumab): the "Analysis" field weighs "strength of evidence, mechanism specificity, safety profile, and translational readiness" and picks the candidate with "direct preclinical and early clinical evidence in dry AMD". **[CODE/log]** — [robin_full.ipynb](https://raw.githubusercontent.com/Future-House/robin/main/robin_full.ipynb)
- Secondary sources confirm no Elo scores are published: "none of them mention Elo ratings … ranked in an LLM-judged tournament" — [search summary](https://arxiv.org/pdf/2505.13400)
- Independent (non-Robin) literature on pairwise LLM ranking notes both support (Elo-from-pairwise tracks accuracy with Spearman >0.9 across benchmarks) and concerns (judges "may reward superficial stylistic cues or display judge biases"; transitivity not guaranteed). — [Remeli & Hardt, ICML 2026](https://icml.cc/virtual/2026/poster/64802); [Elo Uncovered](https://arxiv.org/abs/2311.17295)

### Inferences
- **[INFERENCE]** The "novelty/feasibility score" the task asked about does not exist as a separate numeric score in Robin: novelty and feasibility are two of five qualitative criteria folded into a single pairwise win/loss; the only numeric output is the BTL strength. A battery adaptation that wants explicit novelty vs feasibility axes would have to add them (e.g., two separate tournaments, or a rubric score logged alongside the win/loss).
- **[INFERENCE]** Because the judge prompt places "Strength of Supporting Evidence" first and treats novelty as conditional, the ranking is structurally biased toward well-documented, already-studied interventions (drug repurposing). This is consistent with the dAMD result (ripasudil = already-approved glaucoma drug). For a materials project aiming at genuinely new chemistries, the criteria ordering should be re-weighted deliberately.
- **[INFERENCE]** With 300 games over 30 items each item is judged ~20 times, giving reasonably stable BTL estimates; with the default 3 assays/5 candidates only 3 and 10 games are played and the ranking is weak. A hand-run version with ~10 ideas should do the full round robin (45 comparisons).

### Gaps
- The exact expert-panel protocol used to compute the 7.25/10 agreement (how many experts, which hypotheses set) is in the paper/SI and could not be verified.
- Whether position bias was controlled (e.g., swapping A/B order) is not visible in the code read; `process_comparison_pair` details were only partly inspected.

## Key Question 3 — What makes the workflow "auditable"/traceable (citations, reports)?

### Takeaway
Traceability comes from file-system artefacts at every step: every literature query and answer, every per-hypothesis report (with PaperQA2 citations reformatted to APA and an explicit no-fabrication rule), every pairwise judgement with its written "Analysis/Reasoning", the BTL score table, and every Finch notebook trajectory (viewable on the Edison platform), plus consensus CSVs. The paper additionally reports that human analysts re-analysed the raw data and found a smaller effect than Finch, which is itself a form of audit.

### Cited Findings
- Output tree per run (`robin_output/<disease>_<timestamp>/`): `experimental_assay_literature_reviews/` (one file per query), `experimental_assay_detailed_hypotheses/` (one report per assay), `experimental_assay_ranking_results.csv` ("pairwise comparison results"), `experimental_assay_summary.txt`, `therapeutic_candidate_literature_reviews/`, `therapeutic_candidate_detailed_hypotheses/`, `therapeutic_candidate_ranking_results.csv`, `ranked_therapeutic_candidates.csv` ("final ranked therapeutic candidates and their strength scores"), `therapeutic_candidates_summary.txt`, and after data analysis a `data_analysis/` folder with `consensus_results.csv`, a `results_<timestamp>.json`, and `_experimental`-suffixed versions of the candidate files. **[CODE]** — [README](https://raw.githubusercontent.com/Future-House/robin/main/README.md)
- Each pairwise comparison row stores Winner, Loser, Winner ID, Loser ID and the judge's `Analysis` and `Reasoning` text (parsed from the JSON). **[CODE]** — [utils.py](https://raw.githubusercontent.com/Future-House/robin/main/robin/utils.py)
- Candidate reports are reformatted by an LLM "editor of a scientific journal" to APA 7th, consolidating duplicate PaperQA-style keys (e.g., "smith2000xyz pages 14-16") into single references, marking ClinicalTrials.gov items, and with the rule "MOST IMPORTANTLY, DO NOT MAKE UP ANY REFERENCES THAT ARE NOT IN THE SOURCES LIST … JUST SAY (Unknown Reference)." **[CODE]** — [prompts.py](https://raw.githubusercontent.com/Future-House/robin/main/robin/prompts.py)
- Finch trajectories are retained on the platform; the code logs e.g. "View the final volcano plot at: https://platform.futurehouse.org/trajectories/<id>". **[CODE/log]** — [robin_full.ipynb](https://raw.githubusercontent.com/Future-House/robin/main/robin_full.ipynb)
- The repo ships `examples/` with complete outputs for 10 diseases (Age-Related Hearing Loss, Celiac Disease, Charcot-Marie-Tooth, CKD, Friedreich's Ataxia, Glaucoma, IPF, NASH, PCOS, Sarcopenia) "to help users to understand the depth, format, and typical errors seen in Robin runs." **[CODE]** — [README](https://raw.githubusercontent.com/Future-House/robin/main/README.md)
- Robustness-by-replication: analyses are run as 5 parallel Finch trajectories then combined by a consensus step; for RNA-seq in the paper, "Across eight Finch trajectories, genes recurring in more than half formed a consensus." **[CODE; PAPER-via-secondary]** — [analyses.py](https://raw.githubusercontent.com/Future-House/robin/main/robin/analyses.py); [GitHub issue summary](https://github.com/jjakimoto/research-issues/issues/1656)
- Human audit of the agent's analysis: Finch reported a 7.5-fold increase in phagocytosis MFI for ripasudil vs DMSO; "The paper's own human reanalysis of the same raw data found a significant but smaller 1.75-fold increase." **[PAPER-via-secondary]** — [search summary of the paper](https://www.nature.com/articles/s41586-026-10652-y); [GitHub issue summary](https://github.com/jjakimoto/research-issues/issues/1656)
- Citation quality of the underlying literature agents (PaperQA2, the engine behind Crow): on LitQA2, precision 85.2% ± 1.1% and accuracy 66.0% (human PhD-level baseline 73.8% precision in one summary); for WikiCrow articles 86.1% of cited statements were supported by their citations vs 71.2% for human Wikipedia, with 3.5% uncited statements vs 13.6%. — [arXiv 2409.13740 via search summary](https://www.arxiv.org/pdf/2409.13740); [Wikimedia Research Newsletter](https://meta.wikimedia.org/wiki/Research:Newsletter/2024/September)

### Inferences
- **[INFERENCE]** For a hand/LLM-agent battery workflow, the minimum auditable artefact set is: (i) query list, (ii) per-query cited literature summary, (iii) per-idea structured report with fixed section headings, (iv) a comparisons table with written reasoning per pair, (v) a strength-score table, (vi) a fixed-schema results CSV from the analysis step plus the analysis notebook, (vii) a four-field "insights" record that is literally pasted into the next round's prompts. Robin's traceability is a property of this file discipline, not of the LLM.

### Gaps
- No citation-accuracy audit specific to the dAMD Robin reports (e.g., fraction of hallucinated references in Falcon reports) was found in accessible sources.

## Key Question 4 — What are the published limitations and critiques?

### Takeaway
Stated/observed limitations: Robin produces experimental *outlines* not executable protocols; humans still choose materials and run experiments; Finch output is stochastic and prompt-sensitive (7.5× vs 1.75× human reanalysis); the evidence is a single in-vitro case (ARPE-19 cells, 100 µM, no dose–response, no animal/clinical data, no independent replication, no controlled comparison against human-led workflows); ranking metrics validate judge consistency, not hypothesis truth; the design favours repurposing of well-evidenced compounds.

### Cited Findings
- "Robin produces experimental outlines, not executable protocols." "Finch relies on expert prompt engineering and gives stochastic results. The 7.5-fold versus 1.75-fold gap shows unresolved sensitivity to analysis choices." "The evidence is one in-vitro case. There are no animal or clinical studies, no independent replication, and no controlled comparison against non-agentic or human-led workflows." "Ranking metrics also don't validate the therapeutic hypothesis itself." **[PAPER-via-secondary]** — [GitHub issue summary](https://github.com/jjakimoto/research-issues/issues/1656)
- The authors note "further testing at different doses and longer incubation times would be necessary for definitive comparison" of ripasudil with Y-27632; results were obtained in ARPE-19 cells. **[PAPER-via-secondary]** — [search summary of arXiv 2505.13400](https://arxiv.org/pdf/2505.13400)
- A secondary explainer notes the study "did not establish an appropriate dose, prove safety for this purpose, or show that it improves vision," calling the compounds "experimental leads, not proven treatments." — [WonderBaby explainer (secondary)](https://www.wonderbaby.org/?p=29492)
- Press framing: both Robin and DeepMind's Co-Scientist "are designed to assist researchers in accelerating scientific discovery, not to replace them." — [Nature Asia press release](https://www.natureasia.com/en/info/press-releases/detail/9330) (search-snippet)
- The code itself hard-codes the dAMD assay into the analysis prompts ("Analyze the .fcs files to measure Alexa Fluor 647 signal in live retinal pigment epithelial cells"), i.e., the data-analysis stage is not disease-agnostic without re-prompting. **[CODE]** — [prompts.py](https://raw.githubusercontent.com/Future-House/robin/main/robin/prompts.py)
- Known failure modes visible in the paper run logs: judge JSON-decode errors (2/300 per tournament), file-download failures from Finch trajectories, and the README's admission that example outputs show "typical errors seen in Robin runs." **[CODE/log]** — [robin_full.ipynb](https://raw.githubusercontent.com/Future-House/robin/main/robin_full.ipynb); [README](https://raw.githubusercontent.com/Future-House/robin/main/README.md)
- Bias toward well-studied candidates is built into the prompts: the candidate-generation prompt simultaneously demands "Compounds should be novel for treatment of the disease" and "Strong Target Validation … Relevant Preclinical/Clinical Evidence … commercially available", and the judge makes evidence "Highest Priority" with novelty last and conditional. **[CODE]** — [prompts.py](https://raw.githubusercontent.com/Future-House/robin/main/robin/prompts.py)
- The data-analysis portion requires paid access to the Edison platform ("Finch … currently in a closed beta" at release; "requires access to the Edison platform"), so the full loop is not freely reproducible. **[CODE]** — [README](https://raw.githubusercontent.com/Future-House/robin/main/README.md); [robin_full.ipynb](https://raw.githubusercontent.com/Future-House/robin/main/robin_full.ipynb)
- General critiques of LLM pairwise ranking that apply: Elo/pairwise rankings are sensitive "when dealing with models that exhibit similar performance levels" and transitivity "is not always guaranteed." — [Elo Uncovered (2023)](https://arxiv.org/abs/2311.17295)

### Inferences
- **[INFERENCE]** I found no formal critique explicitly accusing Robin of hallucinated citations; the hallucination risk is addressed defensively in the code (APA reformatter with "(Unknown Reference)" rule) and indirectly via PaperQA2's measured precision (~85%), implying roughly 1 in 7 answered statements can still be wrong. Any hand-run adaptation should budget for manual citation spot-checks.
- **[INFERENCE]** The ripasudil "discovery" is best characterised as literature-grounded mechanism-class extension (ROCK inhibitor Y-27632 → clinically approved ROCK inhibitor ripasudil) rather than de-novo discovery; it demonstrates that the feedback loop can move from a tool compound to a translatable analogue.

### Takeaway

## Appendix — Minimal "Robin-by-hand" recipe distilled from the code (for the battery SAM project) **[INFERENCE, derived from CODE]**

1. **Input**: one phrase naming the problem (Robin: disease name). Battery analogue: e.g., "Li-metal anode SEI instability in anode-free cells".
2. **Assay stage**: write 5 broad (30+ word) literature queries (mechanisms + test methods, no specific interventions) → cited summaries → propose 10 test protocols as JSON `{strategy_name, reasoning}` favouring "simplicity, speed of readout, relevance, direct functional endpoint" → one 4-section report each (Overview / Evidence / Previous Use / Strengths-Weaknesses) → judge all 45 pairs → BTL (`choix.ilsr_pairwise`, α=0.1) → pick top → write a one-sentence goal.
3. **Candidate stage**: 10 queries (5 intervention landscape + 5 mechanism) → cited summaries → exactly 30 single-agent, commercially available candidates in `CANDIDATE/HYPOTHESIS/REASONING` blocks → one 5-section deep report each (Overview / History / Mechanism / Expected Effect in *this* assay / Evaluation) with APA references and "(Unknown Reference)" for anything unverifiable → 300 random pairwise judgements with written Analysis/Reasoning → BTL strengths → CSV.
4. **Experiment**: humans test top-k (Robin: 5, then 10).
5. **Analysis**: 5 independent analysis runs with the same prompt and fixed output schema → consensus run (combine p-values / mode of effect sizes) → LLM produces {drugs tested, summary, questions raised, mechanistic insights} → LLM proposes follow-up assays.
6. **Round 2**: paste those four fields into the query-generation and candidate-generation prompts and repeat step 3 in full (new 30 candidates, new tournament).
7. **Audit**: keep every query, summary, report, comparison row, score table, analysis notebook and consensus CSV; have a human re-analyse raw data before claiming effect sizes (Robin: 7.5× agent vs 1.75× human).
